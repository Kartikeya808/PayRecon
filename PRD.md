## 1. Problem

Indian exporters and freelancers paid from abroad (USD, EUR, GBP) almost never receive the invoiced amount. Correspondent banks deduct fees in transit, the receiving bank converts at a rate below mid-market, and it adds its own charges plus GST on them. Clients also sometimes pay part of an invoice, or pay two invoices in one transfer.

The result: the INR credit on the bank statement doesn't match any invoice, and small businesses reconcile by hand in spreadsheets. They can't tell how much of a shortfall is "normal cost" versus money the client still owes, so they either chase too aggressively or quietly lose money.

## 2. Users

| Persona | Situation | What they need |
| --- | --- | --- |
| Freelancer (primary) | 5–30 foreign invoices/month, paid via SWIFT, Wise, Payoneer, PayPal or similar | "Which invoices are fully paid, and what do I chase?" |
| Small exporter | 20–200 invoices/month, a part-time accountant | Clean match list, shortfall breakdown per payment, export for the accountant |

## 3. Goal and success metrics (for the demo)

The MVP proves one loop end to end: **upload → auto-match → explain the gap → draft follow-up.**

| Metric | Target on the synthetic demo set |
| --- | --- |
| Invoice field extraction accuracy (number, client, currency, amount, date) | ≥ 95% of fields |
| Correct payment→invoice matches | ≥ 90% auto, 100% after agent pass + review |
| Gap breakdown sums exactly to the total shortfall | 100% (enforced by code) |
| Time from upload to reconciled board (20 invoices, 21 payments) | < 90 seconds |
| Model API spend per full demo run | < $1.50 |

## 4. Scope

**MVP (must ship):**
1. Upload invoices (PDF, JPG, PNG) and bank/platform statements (CSV, PDF).
2. Extract structured fields from every document with Muse Spark 1.3.
3. Deterministic matching with a confidence score.
4. Muse Wonder agent resolves low-confidence and complex cases (split payments, one payment covering two invoices) using tools.
5. Gap breakdown per match: intermediary fees, FX spread, bank charges, partial payment / outstanding.
6. Plain-language explanation per match, with the evidence it used.
7. Drafted follow-up email for anything still owed (copy to clipboard; the app never sends email).
8. Visible agent activity trace and a Model API cost meter.

**Stretch (only after MVP is demo-ready):**
- FX loss dashboard: rate received vs mid-market, ₹ lost per transaction, per channel, per month.
- CSV export for the accountant.
- FIRA/FIRC document upload and linking to payments.

**Out of scope:** sending emails, connecting to real bank accounts, tax or GST filing advice, multi-user auth, mobile app.

## 5. User flow

1. **Upload** — drag in invoices and statements. Each file shows a status: queued → extracting → done / needs attention.
2. **Reconcile** — one click runs matching, then the agent pass. Agent activity streams in a side panel.
3. **Board** — table of payments: date, remitter, INR credited, matched invoice(s), status chip (Fully paid · Paid with costs · Partial · Unmatched · Needs review), shortfall in ₹.
4. **Match detail** — drawer with the gap waterfall, the explanation, source evidence (the statement line and invoice fields), and Confirm / Reject / Reassign buttons.
5. **Follow-ups** — list of drafted emails for Partial and "client should have borne charges" cases; edit and copy.

## 6. Core logic

### 6.1 Matching (deterministic first pass)

Score each (payment, invoice) pair from 0 to 1:

| Signal | Weight | Rule |
| --- | --- | --- |
| Invoice number in payment reference/narration | 0.35 | exact or normalized match (strip spaces, dashes, "INV") |
| Remitter ≈ client name | 0.25 | fuzzy match (token-set ratio ≥ 0.8) |
| Amount fits | 0.25 | foreign amount between 90% and 100% of invoice, or implied INR within band of invoice × mid-market rate |
| Currency matches | 0.10 | equal |
| Date plausible | 0.05 | payment 0–120 days after invoice date |

- **≥ 0.85** → auto-match. **0.50–0.85** → send to agent. **< 0.50** → agent checks for split or combined payments, else Unmatched.
- One-to-one assignment via greedy highest-score-first; leftovers go to the agent.

### 6.2 Agent pass (Muse Wonder 1.0)

The agent receives the unresolved payments and open invoices and works through tools. It may only change matches through tools; every tool call is logged to the activity panel.

| Tool | Purpose |
| --- | --- |
| `list_unresolved()` | Unmatched/low-confidence payments with candidate invoices and scores |
| `get_invoice(id)` / `get_payment(id)` | Full records incl. raw statement line |
| `get_mid_market_rate(date, from, to)` | Calls the FX service (§8) |
| `compute_gap(payment_id, invoice_ids[])` | Runs the deterministic breakdown (§6.3) and returns it |
| `propose_match(payment_id, allocations[{invoice_id, amount_fc}], rationale, confidence)` | Records a match as `needs_review` (≥ 0.9 confidence may auto-confirm) |
| `mark_unmatched(payment_id, reason)` | Leaves it for the human |

Agent rules (put in the system prompt): never invent amounts; always call `compute_gap` before proposing; prefer leaving something unmatched over a weak guess; cite which fields drove the decision.

### 6.3 Gap breakdown (pure functions, unit-tested)

Inputs: invoice amount `A` (foreign currency), foreign amount that arrived `F` (if the statement shows it), applied rate `r`, INR credited before bank charges `C0`, bank charges + GST on charges `B` (INR), mid-market rate on value date `m`.

```
expected_inr        = A × m
received_inr        = C0 − B
intermediary_fee    = (A − F) × m          # in-transit deductions
fx_spread           = F × (m − r)          # where r = C0 / F
bank_charges        = B
total_shortfall     = expected_inr − received_inr
                    = intermediary_fee + fx_spread + bank_charges   # assert exact equality (round only for display)
```

**Classification:**
- `A − F ≤ max(fee_cap_fc, 3% × A)` (default `fee_cap_fc` = 50 in invoice currency) → **Paid with costs**.
- Above that → **Partial**; `outstanding_fc = A − F − typical_fee` (typical fee = the cap, configurable), shown as "likely still owed".
- If `F` is missing (statement shows only INR): use implied rate `C0 / A`; if within 2.5% below `m`, treat the whole gap as fees + spread combined; otherwise flag **Needs review** as possible partial.
- If the invoice says the client bears all charges (`OUR`) and fees were deducted anyway → the fee amount is also recoverable and gets a follow-up.

**Worked example (illustrative rates):** Invoice USD 2,000. USD 1,975 arrives (USD 25 correspondent fee). Bank converts at 84.10 vs mid-market 84.95 and charges ₹500 + ₹90 GST.

| Line | ₹ |
| --- | --- |
| Expected at mid-market (2,000 × 84.95) | 169,900.00 |
| Intermediary fee (25 × 84.95) | −2,123.75 |
| FX spread (1,975 × 0.85) | −1,678.75 |
| Bank charges + GST | −590.00 |
| **Received** | **165,507.50** |

Classification: Paid with costs (USD 25 ≤ USD 60 threshold).

### 6.4 Explanation and follow-up (Muse Wonder 1.0)

- **Explanation:** model receives the computed breakdown JSON + source fields and writes 2–4 plain sentences. It must not introduce numbers that aren't in the JSON (validate: every number in the output must appear in the input; regenerate once if not).
- **Follow-up email:** for Partial and recoverable-fee cases. Polite, references invoice number, issue date, invoiced vs received foreign amount, the outstanding amount, and payment details placeholder. Tone options: friendly / firm.

## 7. AI pipeline and model choices

All calls use the OpenAI-compatible endpoint: base URL `https://api.meta.ai/v1`, `Authorization: Bearer $MODEL_API_KEY`. Use the official `openai` npm SDK with `baseURL` overridden.

| Step | Model | Why | Settings |
| --- | --- | --- | --- |
| Invoice & statement extraction | `muse-spark-1.3` | Accepts PDF/image input; ~3–5× cheaper than Wonder | structured output (JSON schema), low reasoning effort |
| Agent pass (tool calling) | `muse-wonder-1.0` | Built for long-running agents and multi-step tool use | tools enabled, medium reasoning effort, max 20 tool turns |
| Explanations & follow-ups | `muse-wonder-1.0` | Quality of the user-facing text is what judges see | low–medium reasoning effort, `max_tokens` 600 |

- Use the **standard tier, not Contributor** — Contributor variants allow Meta to train on inputs, which is wrong for financial documents even in a demo.
- Cache extraction results by file SHA-256 so re-runs never re-extract.
- Keep the agent's system prompt and tool definitions as a stable prefix to benefit from prompt caching.

**Extraction schemas (enforce via structured output):**

```jsonc
// Invoice
{ "invoice_number": "string", "client_name": "string", "client_email": "string|null",
  "issue_date": "YYYY-MM-DD", "due_date": "YYYY-MM-DD|null", "currency": "ISO-4217",
  "total_amount": "number", "bank_charges_terms": "OUR|SHA|BEN|unknown",
  "field_confidence": { "<field>": "0-1" } }

// Statement (array of credit lines; ignore debits)
{ "lines": [ { "value_date": "YYYY-MM-DD", "credited_inr": "number",
  "foreign_currency": "ISO-4217|null", "foreign_amount": "number|null",
  "applied_rate": "number|null", "remitter_name": "string|null",
  "reference": "string|null", "channel": "SWIFT|Wise|Payoneer|PayPal|Other",
  "bank_charges_inr": "number|null", "raw_text": "string" } ] }
```

CSV statements with known headers are parsed deterministically (no model call); unknown CSV layouts go to the model once to produce a column mapping, which is then applied in code.

## 8. Tech stack and architecture

| Layer | Choice |
| --- | --- |
| App | Next.js (App Router) + TypeScript, Tailwind, shadcn/ui |
| DB | SQLite via Drizzle ORM (single file, zero setup) |
| File storage | local `./data/uploads` (gitignored) |
| LLM | `openai` SDK → Meta Model API |
| FX rates | Frankfurter API (ECB reference rates, free, no key; INR supported): `https://api.frankfurter.dev/v1/{date}?base=USD&symbols=INR`. ECB publishes once per business day; weekends snap to the previous business day. Cache rates in SQLite. |
| Tests | Vitest for gap math, matching scorer, number-validation |
| Agent streaming | Server-Sent Events from `/api/reconcile` to the activity panel |

Note: ECB reference rates are an approximation of mid-market. Label them "ECB reference rate" in the UI.

```
app/
  page.tsx                 # upload
  board/page.tsx           # reconciliation board
  followups/page.tsx
  api/upload/route.ts
  api/reconcile/route.ts   # SSE: matching + agent
  api/matches/[id]/route.ts
lib/
  llm.ts                   # single wrapper: cost logging + budget cap
  extract.ts               # Spark 1.3 extraction
  match.ts                 # deterministic scorer
  gap.ts                   # pure money math
  agent/                   # Wonder tools + loop
  fx.ts                    # Frankfurter + cache
db/schema.ts
scripts/generate-demo-data.ts
tests/
```

## 9. Budget and cost guardrails ($150)

Rates (per 1M tokens): Muse Wonder $4.00 in / $0.20 cached / $20.00 out; Muse Spark 1.3 $1.25 in / $0.15 cached / $4.25 out.

| Activity | Rough cost |
| --- | --- |
| Extract one document (Spark 1.3, ~5k in / 1k out) | ~$0.01 |
| Agent pass on 5–8 hard cases (Wonder, ~80k in mostly cached / 10k out) | ~$0.30 |
| Explanation + follow-up per match (Wonder, ~2k in / 500 out) | ~$0.02 |
| **Full demo run (22 docs, ~20 matches)** | **~$1.00 first run, ~$0.80 re-runs (extraction cached)** |

- `MODEL_BUDGET_USD=100` env var: `lib/llm.ts` refuses calls once logged spend passes it, leaving $50 headroom.
- Footer cost meter reads from `llm_calls`.
- **If you also want to run Claude Code itself on Muse Wonder** (the Model API exposes an Anthropic-compatible Messages endpoint for this): coding sessions consume tokens far faster than the app does, at $20/M output. Either build with your regular Claude Code plan and reserve these credits for the app, or cap that usage at ~$80. Check Meta's "Coding agents" docs page for the exact setup.

| Risk | Mitigation |
| --- | --- |
| Model returns wrong numbers | Math only in code; number validator on all generated text |
| Photo invoices extract poorly | Field-confidence scores; low-confidence fields highlighted for edit |

| ECB rate ≠ true mid-market | Label as "ECB reference rate"; rate source configurable |
| Judges can't tell new work from old | Fresh repo, BUILD_LOG, README section |
